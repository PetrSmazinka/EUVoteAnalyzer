1. System overview

The system has a three-layer architecture. The collection layer gathers data from Wikipedia (national election results), the European Parliament Open Data API (political entities and EP groups), and the EP voting API (sessions, roll-call votes, attendance). Extraction of unstructured content (Wikipedia HTML) into structured data uses an LLM (Google Gemini) with schema-validated structured output and a deterministic (temperature=0) configuration. The persistence layer is a relational database whose central entity links a national party to its representation in the European Parliament (EP group membership, MEPs, votes, attendance). The presentation layer is this web application, a tabbed interface over pre-computed analytical outputs (faction/country cohesion, inter-faction agreement, MEP loyalty and participation, voting-category correlations, topic profiles, association rules, anomaly detection).

2. Evaluation dataset

Ground truth covers all 27 EU member states' last two national parliamentary elections (54 country/year records, 454 party entries), built independently of the pipeline under test: seat counts and government status from ParlGov where available, official/news sources and Wikipedia infobox cross-checks otherwise; Wikidata IDs looked up directly, never taken from the pipeline's own extraction output. All results below reflect a single, consistent pipeline configuration: gemini-2.5-flash, temperature=0, schema-validated structured output with up to 5 retries on an invalid response.

3. Phase 1 — Source acquisition

The pipeline is given only (country, election_year) and must discover the correct Wikipedia article itself; this is compared against the ground-truth URL. A raw string-match gives 43/54 (79.6%) exact agreement. Manual, API-verified investigation of all 11 disagreements found that most are not pipeline errors:

4. Phase 2/3 — Content reduction and extraction ablation

Three content-reduction strategies were compared: HTML (cleaned text, the production baseline), Markdown (link/table-preserving conversion), and raw (no reduction). HTML and Markdown were evaluated on the full 54-record set; raw was evaluated on a fixed 10-record subset (Cyprus, Germany, Malta, Portugal, Spain × 2 election years) for cost reasons, with HTML and Markdown re-aggregated over the same 10 records for a matched, like-for-like comparison.

5. Markdown URL-bias in link-heavy tables

In Markdown mode, a results-table cell such as <a href=".../New_Flemish_Alliance">N-VA</a> becomes [N-VA](.../New_Flemish_Alliance); the LLM sometimes extracts the URL-derived full name instead of the visible abbreviation. Checking all 600 extracted party entries across the 54 Markdown records against the source HTML's visible link text found this pattern in 142 entries (23.7%), but it degraded matching accuracy against ground truth in only 19 of those (3.2% of all 600 entries) — the ground-truth dataset itself standardizes on full party names, so most instances of the preference are harmless. The 19 that did cause a mismatch are concentrated among coalition/alliance parties, where the English-translated full name does not correspond to any ground-truth alias, rather than single parties with an established abbreviation.

6. Entity linking and evaluation-leakage firewall

Party-entity resolution uses a deterministic Wikidata-ID → full-name → abbreviation fallback match with no fuzzy/LLM-based matching. A stated methodological rule was applied throughout this project's ground-truth construction: no matching/lookup heuristic developed for ground-truth or evaluation purposes (multilingual Wikidata aliases, manual alliance/rename overrides) was ever ported into the pipeline's own entity-linking code — doing so would let the system under test converge toward its own answer key for reasons unrelated to genuine extraction capability, the same failure mode as train/test leakage.

7. Known, disclosed limitations

  • Entity-linking evaluation (Phase 4) measures against a single-item, ground-truth-derived candidate pool — an upper bound on linking capability, not identical to production's larger, noisier real candidate pool.
  • The raw-mode ablation is a 10/54 sample by deliberate design choice, not cost avoidance: completing the remaining 44 records would only sharpen the Markdown-vs-raw accuracy significance test, which does not change the practical recommendation given Markdown's much larger compression advantage.
  • Exact-match party-name/abbreviation scoring cannot resolve an abbreviation with zero textual overlap against the ground-truth string (e.g. an Estonian native abbreviation against an English-translated full name).
  • Government/opposition-status data available to this application (the "Government/Opposition Loyalty" tab) covers each country's most recent evaluated elections; earlier periods within a given European Parliament term may be shown as opposition by default where no government record exists yet for that period. See the in-app coverage notice on that tab.
